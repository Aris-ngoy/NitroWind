`nitro-wind` brings Tailwind utility classes to React Native with a native C++ engine. Expo Go uses the JavaScript fallback automatically. A development build or bare React Native app loads the C++ engine after you rebuild.

Fully free and open source under the MIT license.

## Why nitro-wind

<AccordionGroup>
  <Accordion title="Native C++ resolution" icon="zap">
    `className` strings are tokenized, parsed, and inflated in C++ on a development build or bare React Native app. Expo Go stays on the TypeScript engine from `nitro-wind-core`.
  </Accordion>
  <Accordion title="Same API as Tailwind" icon="palette">
    Layout, spacing, color, typography, and variant prefixes (`dark:`, `ios:`, `md:`, `active:`) work as utility classes. You do not write a StyleSheet for the common cases.
  </Accordion>
  <Accordion title="Invariant class names stay cheap" icon="gauge">
    Static class names with no variants skip theme and layout subscriptions. The Babel plugin can hoist those literals into `StyleSheet.create`.
  </Accordion>
</AccordionGroup>

## Resolve speed

Resolve Speed times a synchronous, headless `className → style` call. `nitro-wind` exposes `computeStyle()` for that path. NativeWind and Uniwind resolve inside a React render, so they show as unmeasured here and are compared on the Rendering tab of the example app.
